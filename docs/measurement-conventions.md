# 度量与约束的项目约定

> 这几条不是风格偏好，是本项目用 A/B 实测买回来的。
> 每条都注明了依据，方便日后有新证据时推翻它。

## 1. 具体可核对的约束进 prompt；统计量只用于验收与筛选

**依据（正例）**：场景计划的 `必须出现 / 不能发生` 是逐条可判"在不在"的，
实测把约束兑现率从 **58.9% 提到 93.0%**（`eval/run_refine_ablation.py`，n=3，3/3 胜）。

**依据（反例）**：把实测节奏画像（对话占 60%、对话游程 3.3 段、句长收缩 19%）写进提示词，
**两个指标同向恶化**——节奏距离 1.219 vs 0.619（仅胜 2/20）、style 3.25 vs 4.65
（`eval/run_rhythm_ablation.py`）。推测主因是**单位错配**：章级统计被当成 300 字片段的指令，
只能逼出畸形文本。

**因此**：
- 进 prompt：`must_not`、`must_include`、信息边界、套话黑名单、"直接情绪句 ≤ N"
- 不进 prompt：占比、密度、游程、`narrator_distance: 0.35` 这类数值
- 统计量的正当用途是**事后打分**（best-of-N 选稿）与**挑选少样本示例**

## 2. 主观量一律用离散档位，不用两位小数

**依据**：LLM 裁判在**同一输入**上 style 分能从 5 跳到 9，最终靠中位数去噪才稳住
（`eval/run_judge_scale.py`）。连续小数只会更抖，且"0.73"的精确外观会掩盖它其实是猜测。

**因此**：状态变化、心理强度、叙事压力等一律用
`明显下降 / 小幅下降 / 不变 / 小幅上升 / 明显上升`（或 `+1 / 0 / −1`）。
若确实需要连续量，先做**重测信度**：同一段标两遍，一致率不达标就不许驱动下游。

## 3. 任何标签或评分驱动下游之前，先过人工金标准闸门

**依据**：第一版模式标签在人工金标准上准确率仅 **0.396**，被闸门挡下；
修正分类学后 0.789 / kappa 0.666（`eval/run_mode_agreement.py`）。

**最值得记住的一点**：当时**两个机器标注者彼此的一致度（0.675）高于它们各自与人类的一致度**。
也就是说——**分类学的错误，在没有人类基准时看起来完全像健康的一致**。
只靠"两个模型互相验证"会得出完全错误的信心。

**因此**：
- 门槛：准确率 **< 0.6 停工**，先修分类，不得在未验证的标签上继续建模
- 准确率与 **kappa 必须同时报**（类别分布越偏，准确率越具欺骗性）
- 金标准含语料原文 → 存 `style_data/`（已 gitignore），**不入仓库**

## 4. 每加一个评分项做一次 A/B，不一次性上齐权重

**依据**：本项目两次"看起来显然有用"的机制实测失效——
场景对齐召回（style 5.5 vs 4.7，落在噪声内）、节奏先验（见上）。
手调的多项权重里，大概率有一半是噪声。

**因此**：综合评分从 2–3 项起步，每增加一项跑一次 A/B；无提升就不加。

## 5. 能程序算的，不要问模型

程序检测**零成本、零方差、可单测**，还能把违规原文摘出来，让重写指令具体到"删哪一句"。

已经这样做的：n-gram 复述门（实测 0.0%）、套话黑名单、直接情绪句计数、
知识状态推导的 `must_not`、全部纹理指标。

**因此**：新增校验项时先问一句——**这个能不能数出来？** 能就别问模型。

## 负结果照实记录

三次证伪都写进了 commit message 与 README 的「证伪与止损」小节，并保留了 harness。
一个能告诉你"这功能没用"的实验，价值不低于一个成功的功能——它阻止了把假结论写进文档。
